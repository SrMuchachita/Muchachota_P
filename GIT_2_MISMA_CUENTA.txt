=====================================================================
  COMPARTIR CODIGO CON GITHUB - LOS DOS USAN LA MISMA CUENTA
  (La misma cuenta de GitHub abierta en las dos computadoras)
=====================================================================

Reemplaza a: copiar carpeta -> comprimir -> subir a Drive -> descargar
-> descomprimir -> borrar la version vieja.

Repositorio de este proyecto:
  https://github.com/SrMuchachita/Muchachota_P

Como es la misma cuenta, NO hay que invitar a nadie ni dar permisos.
Todo se hace con botones de VS Code.


---------------------------------------------------------------------
PARTE 1 - CONFIGURACION INICIAL (SE HACE UNA SOLA VEZ)
---------------------------------------------------------------------

>>> COMPUTADORA 1 (donde ya esta el proyecto)

  1. Abrir el proyecto en VS Code.
  2. Ctrl + Shift + G (Control de codigo fuente).
  3. En el cuadro "Mensaje" escribir, ej:  Version actual del HMI
  4. Clic en el boton azul "Confirmacion".
     - Si pregunta "No hay cambios staged... ¿agregar todos?"
       -> "Si" (o "Siempre" para que no vuelva a preguntar).
  5. Clic en el boton azul "Sincronizar cambios".
  6. Si pregunta "Esta accion extraera e insertara confirmaciones
     desde y hacia origin/main" -> "Aceptar".
  7. Comprobar en https://github.com/SrMuchachita/Muchachota_P
     que arriba aparece tu mensaje.


>>> COMPUTADORA 2 (la del compañero)

  1. Si no tiene Git: instalar desde https://git-scm.com/download/win
     (opciones por defecto) y reiniciar VS Code.
  2. En VS Code: Archivo -> Cerrar carpeta (sin carpeta abierta).
  3. Ctrl + Shift + P -> escribir "Git: Clonar" -> Enter.
  4. Elegir "Clonar desde GitHub".
     (Como la cuenta ya esta abierta, aparece la lista de repositorios.)
  5. Seleccionar SrMuchachita/Muchachota_P
  6. Elegir la carpeta donde guardarlo (ej. C:\Proyectos).
  7. "¿Abrir el repositorio clonado?" -> "Abrir".

  Listo. Ya tiene todo el codigo. No vuelve a usar Drive.


---------------------------------------------------------------------
PARTE 2 - USO DIARIO (FUNCIONA EN LOS DOS SENTIDOS)
---------------------------------------------------------------------

>>> QUIEN HIZO CAMBIOS - PARA SUBIRLOS:

  1. Ctrl + Shift + G
  2. Escribir un mensaje claro, ej:
       v1.0.83 - cambio trama UART de velocidad
  3. Clic en "Confirmacion".
  4. Clic en "Sincronizar cambios".
  5. Avisar al otro: "ya subi".

>>> EL OTRO - PARA RECIBIRLOS:

  Abajo a la izquierda, en la barra azul, al lado de "main",
  clic en el icono de flechas en circulo (sincronizar):

        ><   main   (flechas en circulo)   <- ese boton

  - A veces salen numeros como "1↓ 0↑": hay 1 cambio para bajar.
  - Si pregunta "extraera e insertara confirmaciones..." -> "Aceptar"
    (o "Aceptar, no volver a mostrar").

  Solo se transfieren las lineas que cambiaron, no todo el proyecto.


---------------------------------------------------------------------
REGLA DE ORO
---------------------------------------------------------------------

  ANTES de empezar a trabajar  -> clic en sincronizar (bajar lo nuevo).
  AL TERMINAR de trabajar      -> Confirmacion -> Sincronizar cambios.

  Pónganse de acuerdo en quien toca que archivo
  (ej. uno trabaja en screens.c y el otro en actions.c).

  OJO con la misma cuenta: en el historial todos los cambios aparecen
  con el mismo nombre (SrMuchachita). Para saber quien hizo que,
  pongan su nombre o iniciales en el mensaje, ej:
       [Juan] ajuste pantalla alarmas


---------------------------------------------------------------------
SI SALE UN CONFLICTO
---------------------------------------------------------------------

Pasa solo si los dos cambiaron LAS MISMAS LINEAS del mismo archivo
sin sincronizar antes. No se pierde nada. VS Code muestra:

  <<<<<<< Cambio actual (el tuyo)
      velocidad = 100;
  =======
      velocidad = 120;
  >>>>>>> Cambio entrante (el del otro)

Encima aparecen botones:
  - "Aceptar cambio actual"    -> te quedas con el tuyo
  - "Aceptar cambio entrante"  -> te quedas con el del otro
  - "Aceptar ambos cambios"    -> se quedan los dos

Eliges, guardas (Ctrl + S) y haces Confirmacion -> Sincronizar cambios.

Si cambiaste algo por error y quieres volver a la version de GitHub:
  Ctrl + Shift + G -> clic derecho en "Cambios"
  -> "Descartar todos los cambios" -> luego sincronizar.

---------------------------------------------------------------------
IMPORTANTE: SINCRONIZAR CODIGO NO ES LO MISMO QUE PUBLICAR OTA
---------------------------------------------------------------------

  Sincronizar (VS Code)  -> sube el CODIGO. NO actualiza los equipos.
  publish.ps1            -> compila, sube el .bin como Release y cambia
                            version.json. SI actualiza los equipos (OTA).
                            (ver COMO_ACTUALIZAR_OTA.txt)

  Orden correcto para publicar una version OTA:
    1. Clic en sincronizar (bajar lo del compañero).
    2. Confirmacion -> Sincronizar cambios (subir tu codigo).
    3. Ejecutar publish.ps1

  Si te saltas el paso 1 y el compañero subio algo, el "git push" del
  final de publish.ps1 falla: el Release se crea pero version.json no
  se actualiza y los equipos NO se enteran de la version nueva.

  Sincronizar solo cambia el codigo. Para que llegue a un equipo hay
  que compilar y flashear (o publicar por OTA).
